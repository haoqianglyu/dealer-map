# 地图中间层级（聚合圈）设计稿

日期 2026-10-21 · 作者 Fable · 范围：地图页 `src/components/AmapView.vue` 的标记层级；只读审阅 + 实测（线上 https://dealermap.haoqianglyu.com，生普账号，1350×700 / 1920×1080 / 2560×1440 @2x），未改代码。

业主原话：「是不是可以根据层级，再插入几个中间的圈」。

---

## 0. 结论

**推荐混合方案：保留现有「区县」行政级，在它和「小区」之间插入一个按屏幕像素距离聚合的「街区簇」级（supercluster 式），并把聚合一直跑到 16 级作为终态；「街道」不做成地图层级，只作为右侧面板的二级列表（第二期）。**

| 级别 | 缩放 | 一个圈 = | 文字 |
|---|---|---|---|
| ① 区县 | z < `ZOOM_CLUSTER`（≈11.5，见 §2.1） | 一个区县的全部项目 | 区县名（我们画；高德不画字） |
| ② 街区簇 | `ZOOM_CLUSTER` ≤ z < 14 | 屏幕上 64 px 内的若干小区 | 只标「k 小区」；地名交给高德注记 |
| ③ 小区 | 14 ≤ z < 16 | 一个小区（胶囊带小区名）；48 px 内仍合并 | 小区名（合并时「A 等 k 小区」） |
| ④ 终态 | z ≥ 16 | 不再拆分：同坐标 / 分期的小区并成一个胶囊 | 同 ③，点击弹窗按小区分组 |

为什么不用「街道」做层级（方案 2）：
1. **高德没有街道边界。** 实测 `AMap.DistrictSearch({level:'district', subdistrict:1})` 对滨湖区返回 9 个街道（胡埭镇 / 河埒 / 雪浪 / 华庄 / 荣巷 / 蠡园 / 蠡湖 / 太湖 / 马山）只有中心点，`boundaries` 为空。无边界就只能「就近中心点」归属——实测把太湖新城一带 53 个项目的簇归到了「雪浪街道」，边界附近的滨湖小区归到了「梁溪区」，名字会错。
2. 要拿准确街道得对每个小区做一次逆地理编码（`addressComponent.township`），当前 geo-seed / 共享缓存都没存这个字段（221 条已确认记录里 `a` 字段 0 条带街道）——多一轮请求 + 缓存结构改动，而个人 key 的配额本来就是瓶颈。
3. 街道大小悬殊（宜兴 18 个、新吴 6 个；一个街道里也可能 50 个小区），圈还是会在大街道里爆开；像素聚合天然按屏幕密度自适应，1350 和 2560 的屏都合适。
4. 街道名放在地图上会和高德 12–13 级自己画的镇街名重复——正是上一轮反复修的「同名两份」问题。放在右侧面板里没有这个矛盾。

## 1. 实测现状（为什么要做）

缩放到城市视野的级别因屏幕而异：**1350×700 → z 9.86，1920×1080 → z 10.7，2560×1440 → z 11.16**（`fitBounds` 结果）。现状 `ZOOM_SPLIT = 12`，于是：

| 场景（滨湖区居中，1350×700） | 标记数（地图区可见） | 两两重叠对数 | 被压住的标记 |
|---|---|---|---|
| z 11 / 11.5 | 5 / 4 个区县圈 | 0 | 0（但画面大片空白，见 `04-binhu-z11.5`） |
| **z 12（点区县圈落到的级别）** | **105**（全市 188 个已定位小区全部上图） | **92** | **80** |
| z 13 | 53 | 29 | 32 |
| z 14（胶囊） | 26 | 7 | 14（胶囊互压：太湖国际聆湖 1+1、融创熙园 / 融创花溪美墅、建发和玺 9） |
| z 15 | 8 | 1 | 2 |
| z 16 | — | — | 仍有 **6 个标记坐标完全相同**（分期 / 同名查询落到同一点），放大到底也分不开 |

1920×1080 下 z12 地图区可见 124 个标记，锡山 / 梁溪交界处「1」字圈叠成串（`05-xishan-z12`）。

同一批点按像素距离聚合的模拟（真实坐标，1350×700，滨湖居中）：

| z | 半径 40 px | 56 px | **64 px** | 72 px | 96 px |
|---|---|---|---|---|---|
| 12 | 100 簇（47 多点） | 80（46） | **≈70（≈45）；视野内 33 个圈** | 66（37） | 51（31） |
| 13 | 136（37） | 120（43） | ≈110（≈45） | 104（47） | 89（47） |
| 14 | 160（26） | 147（33） | — | 140（34） | 126（41） |
| 15 | 180（8） | 172（14） | — | 165（21） | 153（30） |
| 16 | 185（3） | 183（5） | — | 181（7） | 178（10） |

（括号 = 含 ≥2 个小区的簇；全部 188 个点，不限视野。）64 px 在 12 级把视野内 105 个圈收到 33 个，最大簇 53 个项目 / 9 个小区，圈最大 64 px，仍能一眼读；96 px 会把太湖新城整片并成 73 个项目的一个大圈，信息量反而不如区县级。

另外两处与本题相关的现状：
- **区县圈数字 ≠ 右侧面板数字**：滨湖区圈 155，面板 257。圈只统计「已定位小区」的项目，面板统计全部。见 §9。
- 热力模式不受层级影响（每小区一盏灯），只在区县级画「区县名 + 数」暖色标签。

## 2. 层级与阈值

### 2.1 常量

```js
// AmapView.vue
const ZOOM_NAMED = 14      // 不变：≥14 小区名进胶囊
const ZOOM_TERMINAL = 16   // 聚合查询的最大级别；再放大也不拆
// 区县 → 街区簇 的分界随屏幕走：城市视野再放大约一级就进入簇级
//   1350×700: fit 9.86 → 10.8（下限）；1920: 10.7 → 11.5；2560: 11.16 → 11.8（上限）
const zoomCluster = () => clamp((fitZoom ?? 10.7) + 0.8, 10.8, 11.8)
```

`fitZoom` = 最近一次 `fitBounds()` 为 `props.fit`（城市适配）算出的 zoom，存成模块变量；首次适配前用 11.5 兜底。若嫌动态值难测，退一步用固定 `11.5`（2560 的 11.16 仍是区县级），代价是 1350 下 10–11.5 之间区县圈显得稀。

`levelFor(z)`：`z < zoomCluster()` → `district`；`< 14` → `cluster`；`< 16` → `named`；否则 `terminal`（③ 和 ④ 渲染规则相同，只差「点击簇是否还能继续拆」）。

### 2.2 高德底图要素（文字只有一个来源）

| 级别 | `map.setFeatures` | 我们画的字 | 高德画的字 |
|---|---|---|---|
| ① 区县 | `['bg','road']`（现状） | 城市名、区县名 | 无 |
| ② 街区簇 | `['bg','road','building','point']`（= 现状 ≥12 的设置，提前到 `zoomCluster`） | 数字、「k 小区」、「N 告警」 | 区县 / 镇街 / POI 名 |
| ③④ 小区 | 同上 | 胶囊里的小区名（数据标签） | 同上 |

关键：②级我们**不写任何地名**，所以不可能和高德注记重复；①级高德不写字，所以区县名只有我们一份（现状规则不变）。

## 3. 聚合算法

用 `supercluster`（npm，≈4 KB gzip，依赖 kdbush）。两个索引，半径不同：

```js
import Supercluster from 'supercluster'
const k = Math.max(1, props.scale)            // 2560 下界面放大 1.33，半径同比放大
const common = {
  extent: 256,            // 高德按 256 px 瓦片计 zoom（实测 z12 / 北纬31.5° 分辨率 32.6 m/px），
                          // extent 256 时 radius 的单位才是高德屏幕像素
  minPoints: 2,
  map: (p) => ({ n: p.n, k: 1, rank: p.rank, alarms: p.alarms, pulse: p.pulse, top: p.name, topN: p.n, dist: p.district }),
  reduce: (acc, p) => {
    acc.n += p.n; acc.k += p.k
    acc.rank = Math.max(acc.rank, p.rank)
    acc.alarms += p.alarms
    acc.pulse = acc.pulse || p.pulse
    if (p.topN > acc.topN) { acc.top = p.top; acc.topN = p.topN }
  },
}
const idxCluster = new Supercluster({ ...common, radius: 64 * k, minZoom: 10, maxZoom: 13 }) // ② 用
const idxNamed   = new Supercluster({ ...common, radius: 48 * k, minZoom: 14, maxZoom: 16 }) // ③④ 用
```

- 输入点 = `props.communities`（只有已确认坐标的小区；未定位的照旧不上图），每点 `properties`：`key, name, n = projects.length, rank = stateRank(worstState(projects)), alarms = alarmCount(projects), pulse = hasNewAlarm(projects), district`。
- 查询：`idx.getClusters([w, s, e, n], zq)`，`zq = Math.min(16, Math.floor(map.getZoom()))`；bbox = `map.getBounds()` 四边各外扩 25%（平移时少闪）。小数级别用 `floor`：12.9 级用 12 级的簇，圈只会更疏不会更密。
- 终态：`zq` 封顶 16，所以同坐标 / 分期的点永远是一个簇（`getClusterExpansionZoom(id) > 16`），点击走分组弹窗而不是继续缩放。
- 簇坐标 = 成员均值（supercluster 默认，不按项目数加权），圈落在地理中间。
- 重建时机：`communities` 变化（地理编码是渐进的，**防抖 300 ms**）、告警 60 s 刷新后状态有变化、筛选切换。5k 点建索引 ≈ 20–40 ms，可接受；不要在 `zoomend` 里重建。
- 区县级（①）不用索引，沿用 `props.districts`。

## 4. 圈的外观

### 4.1 尺寸与数字（CSS px，再乘 `--k`）

| 级别 | 直径 | 公式 | 数字字号 |
|---|---|---|---|
| ① 区县 | 44–88（现状） | `clamp(44, 36 + 6·√n, 88)` | 20；n ≥ 1000 时 16 |
| ② 簇 / ②③ 单小区圆 | **28–64** | `S = clamp(28, 22 + 5.5·√n, 64)` | S<36: 13 · 36–43: 14 · 44–55: 15 · ≥56: 16 |
| ③④ 胶囊 | 高 = S（通常 28–34） | 同上（n = 胶囊内项目数） | 13 |

对照：n=1→28，2→30，4→33，9→39，16→44，25→50，36→55，49→61，≥60→64。

- **n 永远是项目数**（和现状一致）；小区数 k 只出现在标签里。
- 数字格式：`fmtNumber`（千分位，`tabular-nums`），不用 1.2k 之类缩写（业主要读准确数）。
- **点按面积 ≥ 44 px**：`.dm-mk` 外包一个 `min-width/min-height: calc(44px * var(--k))` 的透明容器作为 Marker content（圆居中），圆的视觉尺寸不变。现状 26–40 px 的圈在电视 / 触摸屏上不达标。

### 4.2 状态与告警（逐级上卷）

与现状同一套：圈色 = 成员里最严重状态（`rank` 取最大），右上角「N 告警」= 成员进行中一级告警数之和（`alarms` 求和），1 小时内有新告警则脉冲（`pulse` 或）。`reduce` 已经把这三项上卷到任何一级，所以**从区县的红圈一路点进去，每一级都至少有一个红圈，直到胶囊、再到弹窗里红点的那个项目**。

角标样式不变；簇级圈 ≥ 44 px 时角标 20 px 高，小圈 18 px（沿用现状两档）。

### 4.3 「簇」和「一个小区多个项目」要看得出区别

现状一个「29」= 湖玺庄园 29 个项目；簇级的「29」可能是 14 个小区。多小区簇（k ≥ 2）加一道**叠环**：

```css
.dm-mk--cluster::before { content:''; position:absolute; inset: calc(-5px * var(--k)); border-radius: 50%;
  border: 1px solid color-mix(in srgb, var(--c) 45%, transparent); }
.dm-mk--named.dm-mk--cluster::before { border-radius: 999px; }
```

图例「?」弹层加一行「双环 = 多个小区合并」。

### 4.4 标签规则（防重复 / 防压字）

| 级别 | 单小区（k=1） | 多小区簇（k≥2） |
|---|---|---|
| ① | — | 区县名（现状） |
| ② | 不标（现状 12–14 也不标） | 圈下 `<small>k 小区</small>`，11 px，#9fc0e0，描边同现状 |
| ③④ | 胶囊「n + 小区名」（现状） | 胶囊「n + 最大小区名 + <small>等 k 小区</small>」 |

避让（每次渲染后同步做一遍，可见项 ≤ 150，O(m²) 可忽略）：
1. 排序优先级：状态 rank 降序 → 告警数降序 → n 降序。
2. 依次放置；一个标签的矩形若与**其它**圈的矩形（外扩 4 px）或已放置的标签相交 → 去掉这个标签，圈保留。
3. ③④ 级胶囊撞胶囊：低优先级的那个退化为无名圆（`dm-mk--named` 去掉，保留数字、角标、叠环）。
4. 一屏之内不允许出现两个相同文本（用 `Set` 兜底）。

## 5. 点击（电视 / 触摸：全部单击，无悬停依赖）

| 点的是 | 行为 |
|---|---|
| ① 区县圈 | 现状 `zoomTo(d.points, d.lnglat)`，把最后的 `if (zoom < ZOOM_SPLIT) setZoom(ZOOM_SPLIT)` 改成 `< zoomCluster()` → 落到②级 |
| ② 簇 / ③ 合并胶囊，且 `ez = idx.getClusterExpansionZoom(id) ≤ 16` | `map.setZoomAndCenter(ez, clusterLngLat, false, 350)` 再 `panBy` 让出侧栏（复用 `centerOn`）。`ez` 是刚好拆开的整数级，通常 +1～+2 级，不会一下跳到底 |
| ④ 终态簇（`ez > 16`） | 打开分组弹窗（§5.1） |
| 单小区圆 / 胶囊 | 弹窗（现状） |
| 右侧告警行 → `focus` | `setZoomAndCenter(16, c.lnglat)`，同步重算簇，找到**包含该小区 key 的项**（单点或终态簇），打开弹窗并展开该项目的告警（现状 `focusCommunity` 用的是 z≥15 + 只找单点，合并胶囊时会找不到） |
| 空白 | 关弹窗（现状） |

### 5.1 分组弹窗（终态簇）

沿用 `.dm-pop`，宽 360：
- 头：`<b>太湖国际聆湖 等 2 小区</b>` / `滨湖区 · 3 个项目 · 1 告警`
- 列表按小区分组：组头一行（小区名 · 项目数，`.al--note` 样式，28 px 高），下面是现状的项目行；有进行中告警的项目默认展开（现状逻辑）。
- 跨区县的簇（少见，边界处）头部写「滨湖区 / 梁溪区」。
- 前 5 行 + 「查看全部 n 个项目」规则不变。

## 6. 拆分 / 合并动画

- 触发：`zoomend` / `moveend` 重算后，用 id 做 diff（见 §8），新出现的项做入场，消失的项做退场。
- **拆分（放大）**：新项从其父项的屏幕位置平移到自身位置，`240 ms cubic-bezier(.2,.7,.2,1)`，透明度 0→1。父项查找：对上一帧每个簇 `idx.getLeaves(id, Infinity)` 得到叶子 key 集合，新项任一叶子命中即为父（≤5k 叶子，一次遍历）；单点的父 = 包含它的旧簇。
- **合并（缩小）**：新簇 `scale .7→1`，160 ms；旧子项原地淡出 120 ms（不做汇聚位移，缩小时镜头本身在动，再加位移会乱）。
- 实现：动画只作用在 Marker content 内层 `.dm-mk` 的 `transform / opacity`（高德自己用外层 `.amap-marker` 定位，不冲突）；先设 `transform: translate(dx,dy)`，下一帧清零触发过渡。
- `prefers-reduced-motion: reduce`：只做 120 ms 淡入淡出。
- 捏合 / 滚轮过程中不重算（现状也只在 `zoomend` 算），DOM 标记像素尺寸不随手势变化，天然稳定。

## 7. 热力模式、右侧面板

**热力**：不聚合（暖光本身就是聚合视图），保持每小区一盏灯；唯一改动是「区县名 + 数」暖色标签的显示条件从 `level === 'district'` 跟着改成 `z < zoomCluster()`（同一个常量）。热力下 ② 级不额外画数字——想看数就切回点位。

**右侧「各区项目」面板**（推荐分两步）：
- 第一步（随本期）：面板**反映视野**——视野内有标记的区县行加左侧亮条，占视野 ≥ 70% 标记的区县行加粗并在数字后缀「视野内 n」；行可点（行高提到 40 px），点击 = 点该区县圈。标题不变。
- 第二步（街道数据就绪后）：z ≥ `zoomCluster()` 且 ≥ 70% 可见标记属于同一区县时，标题切成「滨湖区 · 各街道」，行 = 街道（只算已定位项目，标题旁小字注明），标题左侧「‹ 无锡市」点回。街道归属来自逆地理编码 `township`，**写进共享缓存**（OSS 记录加 `township` 字段；FC 接口透传），不用就近中心点估算。

## 8. 性能（现在 ~700 项目 / 188 点，按 5k 点设计）

- 索引：O(n log n)，5k 点 20–40 ms，只在数据变化时建（防抖 300 ms），不在缩放事件里建。
- 查询：`getClusters` 每次 < 1 ms；`zoomend` + `moveend` 各触发一次。
- DOM：**只渲染 bbox（外扩 25%）内的项**；现状的「`map.remove(全部)` + `map.add(全部)`」改成按 id diff，未变的标记不动，只更新内容变化的（`setContent`）。
  id：单点 = 小区 key；簇 = `c:${zq}:${lng.toFixed(5)},${lat.toFixed(5)}`（supercluster 的 `cluster_id` 重建后会变，不能直接当 key）。
- 任何级别一屏的项上限实际由半径决定：64 px 半径在 1350×700 的地图区最多 ≈ 150 个圈，2560 下 ≈ 260；标签避让的 O(m²) 在这个量级可以忽略。
- 内存：索引里只放坐标 + 上卷属性，项目数组仍留在 `communities` 里按 key 取。

## 9. 顺带发现（不属于本题，但会被问）

1. **区县圈 155 vs 面板 257**（滨湖）：圈只算已定位。建议区县圈改成算该区**全部**项目（它是行政汇总，和面板、KPI 口径一致），簇 / 小区级天然只有已定位；区县弹窗或状态行写「其中 102 个未定位」。否则业主会问为什么两边对不上。
2. 右侧「小区数 340」与状态行「341 小区」差 1（口径不同），看是否统一。
3. 高德 12–14 级 POI 注记偏亮、偏密（上轮已记），②级开始就会和簇同屏，仍建议后续跟进。

## 10. 实施清单（给工程）

1. `npm i supercluster`；新建 `src/geo/cluster.js`：`buildIndexes(communities, k)`、`query(level, bbox, zq)`、`parentsOf(prevItems, nextItems)`。
2. `AmapView.vue`：
   - `ZOOM_SPLIT` → `zoomCluster()`（§2.1），`levelFor` 四级；`fitBounds` 记录 `fitZoom`。
   - `renderMarkers`：① 不变；②③④ 走索引 + diff + 标签避让 + 动画；`markerHtml` 增加 `cluster`（叠环）、`k`、`sub`（k 小区）。
