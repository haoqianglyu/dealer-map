# 离线项目灰显 — 设计意见

2026-10-21 · Fable · 线上实测 1350×700 @2x（生普会话，弹窗/胶囊内临时注入样式看过效果，未改代码）。数据：无锡 595 项目在线 495 / 离线 100；336 小区 = 38 全离线 / 39 部分 / 259 全在线，已定位 185 小区里约 20 个会变灰（≈11%，不算多，灰不会压过蓝）。

1. **弹窗行点：同意，但别用 `state='offline'`。** `states.js` 里 offline rank 1 > normal，走 `worstState` 一个项目离线整个小区就灰，和第 2 条冲突。给项目加独立字段 `online: true|false|null`，颜色仍由 alarm/warning 决定，无告警且 `projects.every(!online)` 才灰。点 8 px 不变，实心 `#8a9bb3`（legend 已经在用这个灰，别再造一个）；名字降一档 `#b7d3f0`（不要 50% 透明，电视上会糊），面积/详情不动。排序：告警 → 预警 → 离线 → 正常（离线对售后是待办，不能沉到正常后面）。
2. **全离线才灰：同意。** 胶囊/圆：边框 `color-mix(#8a9bb3 70%, transparent)`、填充 `#8a9bb3 10%`、去掉 inset 发光（「灯灭了」）、数字 `#c5d2e0`、小区名 `#9fb0c6`，整体不用 opacity（点按区域和叠环要保持清楚）。与「未定位」不冲突（未定位根本不上图，只在列表黄标）；与「正常」靠色相区分（青 vs 灰），与「无告警」是同一件事所以不需要再区分。部分离线：标记照常，弹窗头 `滨湖区 · 29 个项目 · 1 告警 · 3 户离线`（灰字，和红字告警并排，实测可读）。
3. **告警永远赢：同意。** 离线 + 进行中一级告警 = 红圈 + 角标 + 脉冲，弹窗里该行红点、名字后不加任何「离线」字——通讯故障类告警本来就对应离线，两处标反而重复。
4. **簇 / 区县不变色、不加角标：同意**，但规则统一为「成员全部离线才灰」适用于任何级别（2–3 个小区的簇会出现全灰，很合理）。不要比例环：28–40 px 的圈上已有叠环 + 脉冲环，第三道环没人读得出来。离线数的上卷放两处就够：弹窗头、右下状态行。
5. **图例 / 统计：** legend 已有「离线」项，文案不动；「?」说明加一句「灰圈 = 小区内项目全部离线，部分离线见弹窗」。状态行改成 `已定位 185 / 336 小区 · 在线 495 / 595 · 告警 22:31 更新`（去掉「已加载 702 个项目」，1350 下才放得下，702 在 KPI 已有）。热力不变。
6. **售后要不要单独的离线列表 / 筛选：要，但第二期，且不加面板**（1350×700 右侧已满）。做法：点图例「离线」= 筛选模式，非离线标记降到 25%，状态行变 `离线 100 项目 / 77 小区 · 点图例恢复`，再点取消；图例项要补 40 px 点按区（现在只有 ? 有）。
7. **边缘：** 拉取失败 → 沿用上一次结果最多 5 分钟并在状态行加「在线状态 22:25 未更新」，超过 5 分钟 → unknown：标记全部按在线画，弹窗点改空心灰圈 `1.5px #8a9bb3`（实测空心圈读作「不知道」，实心读作「离线」，正好分工），永远不全灰。`ids:[]` 且 200 也当 unknown。抖动：弹窗点即时变，标记变灰要连续 2 次轮询都离线（避免每 60 s 闪色）。实测另一问题：22:31 无操作时地图自己从 z16 退到 z13 两次，轮询刷新只能 `setContent` 变化的标记，绝不能 fitBounds / 全量重建。
8. **离线多久（API 不给）：** 本地记 `localStorage.dmOfflineSince[id] = 首次看到离线的时间`，上线即删；弹窗行尾灰字 `离线 ≥ 2 小时` / `≥ 3 天`（「≥」是实话：只从本屏开始观察算起）。有进行中「通讯故障」告警的，用告警 ts 代替，更准。≥ 7 天标「长期离线」并沉到本小区最后（多半是停用/拆机，不该天天占着售后视线）。真要准确值得让后端在该接口加 `offlineSince`。
9. **浅色主题：** 灰改 `#6b7a90`（边框/点），填充 8%，名字 `#5b6b80`；原则是灰的饱和度和对比度都要低于「正常」色，且不能和浅色底图的路网灰撞（高德浅色路是 #fff/#e6e6e6，够远）。建议现在就把灰抽成 `--dm-offline` token 放 global.scss，和 `--dm-text-*` 一起换。
